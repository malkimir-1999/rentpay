# Design system

RentPay uses a light-first, professional automotive language with Inter, a soft grey canvas, pale grey hero and chrome, frosted white cards, near-black headings, and a deep green primary action. This September 2026 visual revision was explicitly requested by the product owner and supersedes the earlier orange/blue brand direction; it does not change domain or security architecture. CSS custom properties in `apps/web/app/globals.css` are the source of truth for colors, typography, spacing, radii, shadow, transitions, and layers; CSS Modules consume those tokens. Ant Design is configured once through `ConfigProvider` in `apps/web/theme.ts`, mirroring the same values for its static theme configuration.

Shared primitives in `apps/web/components/ui.tsx` cover shell/navigation, page structure, status, empty/error/loading, search/filter, data table, confirmation, responsive drawer, activity, money, and date display. Use semantic controls, visible keyboard focus, labels, reduced-motion behavior, and mobile navigation. Do not use inline styles or add a second UI framework.

Marketing surfaces use an original unbranded silver crossover cutout with layered operational previews. Marketing sections reveal on entry using a small IntersectionObserver; content remains visible without JavaScript and reduced-motion users see no movement. Authentication, onboarding, and the signed-in business/platform shells share the same tokens and controls. Public business sites may later select independent customer-facing themes; those themes must not alter the RentPay operations dashboard. The builder itself and its editable themes are later product modules. Current signed-in screens are navigation and setup foundations, not full later-phase operational modules.
